## 🚀 Step-by-Step Deployment Guide

### STEP 1 — Local Development Setup

```bash
# 1. Bootstrap project
npx create-next-app@latest souqpilot --typescript --tailwind --app
cd souqpilot

# 2. Install dependencies
npm install @aws-sdk/client-s3 @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner \
  @prisma/client bcryptjs jsonwebtoken resend stripe zod

npm install -D prisma @types/bcryptjs @types/jsonwebtoken

# 3. Initialize Prisma
npx prisma init

# 4. Copy prisma/schema.prisma from deliverables
# Copy .env.local from template above

# 5. Run migrations
npx prisma migrate dev --name init

# 6. Generate Prisma client
npx prisma generate

# 7. Start dev server
npm run dev
```

---

### STEP 2 — AWS S3 Private Bucket Setup

```bash
# Via AWS CLI:
# a) Create a PRIVATE bucket (block all public access)
aws s3api create-bucket \
  --bucket souqpilot-private-files \
  --region us-east-1

# b) Block ALL public access
aws s3api put-public-access-block \
  --bucket souqpilot-private-files \
  --public-access-block-configuration \
  "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# c) Enable server-side encryption
aws s3api put-bucket-encryption \
  --bucket souqpilot-private-files \
  --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

# d) Create IAM policy (principle of least privilege)
# The app user needs ONLY: s3:GetObject, s3:PutObject, s3:DeleteObject, s3:HeadObject
# on arn:aws:s3:::souqpilot-private-files/*
```

**IAM Policy JSON:**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject",
        "s3:HeadObject"
      ],
      "Resource": "arn:aws:s3:::souqpilot-private-files/*"
    }
  ]
}
```

---

### STEP 3 — Stripe Webhook Setup

```bash
# Install Stripe CLI
brew install stripe/stripe-cli/stripe

# Login
stripe login

# For local development — forward events to your dev server
stripe listen --forward-to localhost:3000/api/webhooks/stripe

# The CLI prints your webhook secret: whsec_xxxxx
# Add it to .env.local as STRIPE_WEBHOOK_SECRET

# Register events to forward (only what you need):
stripe listen \
  --events payment_intent.succeeded,payment_intent.payment_failed,charge.refunded,checkout.session.completed \
  --forward-to localhost:3000/api/webhooks/stripe

# For production — register via Stripe Dashboard:
# Developers → Webhooks → Add endpoint
# URL: https://yourdomain.com/api/webhooks/stripe
# Events: same four above
```

### STEP 4 — PayPal Webhook Setup

```
1. Go to developer.paypal.com → My Apps & Credentials
2. Create app → get Client ID + Secret
3. Under Webhooks → Add Webhook
   URL: https://yourdomain.com/api/webhooks/paypal
   Events: PAYMENT.CAPTURE.COMPLETED, PAYMENT.CAPTURE.DENIED, PAYMENT.CAPTURE.REFUNDED
4. Copy the Webhook ID → PAYPAL_WEBHOOK_ID in .env
5. For sandbox testing: use api-m.sandbox.paypal.com as PAYPAL_API_BASE
```

### STEP 6 — Deploy to Vercel

```bash
# 1. Install Vercel CLI
npm install -g vercel

# 2. Deploy
vercel --prod

# 3. Add environment variables in Vercel Dashboard:
#    Settings → Environment Variables
#    Add all variables from .env.local

# 4. Important: Stripe webhook route must disable body parsing
#    (already handled by reading req.text() in the route handler)

# 5. Set function timeout for webhook routes (Vercel Pro: 60s)
#    In next.config.js:
#    export const maxDuration = 60; // add to each webhook route.ts
```

### STEP 7 — Production Checklist

```
Security
  ✅ S3 bucket is PRIVATE (no public GetObject)
  ✅ Stripe webhook signature verified via HMAC-SHA256
  ✅ PayPal webhook verified via API callback
  ✅ JWT access tokens expire in 15 minutes
  ✅ Refresh tokens are SHA-256 hashed before storage
  ✅ Download tokens are opaque UUIDs (S3 key never exposed)
  ✅ Download links revoked immediately on refund
  ✅ All API inputs validated with Zod
  ✅ Timing-safe password comparison (bcrypt always runs)
  ✅ 404 returned instead of 403 for unauthorized token access

Reliability
  ✅ Webhook idempotency via provider_event_id UNIQUE constraint
  ✅ All fulfillment inside DB transactions (atomic)
  ✅ Optimistic locking on download counter increment
  ✅ Stripe returns 500 on handler error → triggers retry

Performance
  ✅ Prisma client singleton (no connection pool exhaustion)
  ✅ Indexed: users.email, orders.payment_intent_id, download_links.token
  ✅ Pagination on product listing API
```
